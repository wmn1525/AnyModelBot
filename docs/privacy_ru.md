# Данные и приватность

[简体中文](./privacy.md) | [English](./privacy_en.md) | [日本語](./privacy_ja.md) | [한국어](./privacy_ko.md) | Русский

**Главное:** разговоры, память, файлы и ключи хранятся на вашем устройстве; всё отправляемое модели идёт выбранному поставщику: напрямую с официальным API-ключом, иначе через Modelflare. Мы не обещаем полного отсутствия рисков: данные, отправленные модели, покидают устройство.

Здесь описано, какие данные AnyModelBot хранит и где, что отправляет наружу и как это удалить. Вопросы: [support@anymodel.bot](mailto:support@anymodel.bot).

## Папка данных

| Способ запуска | Папка данных |
| :--- | :--- |
| Приложение · Windows | `%APPDATA%\anymodel bot\data` |
| Приложение · macOS | `~/Library/Application Support/anymodel bot/data` |
| Приложение · Linux | `~/.config/anymodel bot/data` |
| Командная строка `npm start` | `./data`, изменяется через `AMB_DATA_DIR` |
| Docker | `/data` внутри контейнера; в примере README подключён том `amb-data` |

## Доступ к локальной консоли

- По умолчанию консоль слушает `127.0.0.1:3600` и недоступна из локальной сети или интернета.
- Настольное приложение при каждом запуске создаёт случайный токен, чтобы другие локальные программы не могли напрямую вызывать API управления.
- Для нелокального адреса, например `0.0.0.0` в Docker, токен обязателен. Он хранится в файле `ui-token` в папке данных; Docker: `docker exec amb cat /data/ui-token`.
- Не открывайте порт 3600 напрямую в интернет. Для удалённого доступа используйте собственную VPN или обратный прокси с авторизацией.

## Вход в Modelflare

- Используется OIDC authorization code с PKCE (RFC 7636) для нативных приложений по RFC 8252. AnyModelBot — публичный клиент без клиентского секрета; результат приходит на временный loopback-порт.
- Вход происходит на modelflare.dev; AnyModelBot не видит ваш пароль.
- Доступ устройства можно отозвать в разделе авторизованных приложений профиля Modelflare. Выход из приложения также отзывает авторизацию и удаляет ключи, выданные устройству и его ботам.

## Запросы к моделям и Modelflare

- Встроенный magpie отправляет запросы в Modelflare, который передаёт их выбранному поставщику.
- Запрос содержит нужное модели: инструкцию, историю разговора, используемую память, содержимое файлов, результаты инструментов и, при управлении компьютером, снимки экрана.
- Заголовок `X-Modelflare-Skill: anymodel-bot/<version>` позволяет Modelflare определить источник. Ссылки на Modelflare из приложения содержат `utm_source=anymodelbot`. Когда приложение открывает страницу пополнения, после `#` в адресе передаётся идентификатор аккаунта из ID-токена входа (`#amb_account=…`, не секрет), чтобы страница Modelflare проверила, что в браузере выполнен вход в тот же аккаунт; часть после `#` не отправляется серверам, CDN и скриптам аналитики. Уведомление «Конфигурация ключей изменена» сравнивает HMAC ключа, вычисленный локально со случайной солью; ни ключ, ни его хеш для этого не сохраняются и не отправляются.
- Modelflare хранит журналы запросов. Состав и сроки — в [Центре доверия](https://modelflare.dev/trust?utm_source=anymodelbot&utm_campaign=amb_readme). Обработка данных поставщиками моделей регулируется их собственными условиями.

## Свои официальные API-ключи

- Если ввести официальный ключ OpenAI, Anthropic или другого поставщика на приветственном экране или в разделе «Настройки → Модели», встроенный шлюз будет отправлять запросы к его моделям напрямую. Они не проходят через Modelflare и не содержат заголовка `X-Modelflare-Skill`. Хранение данных регулируется условиями этого поставщика.
- Адреса поставщиков зафиксированы в приложении и не меняются ни в интерфейсе, ни через его API, поэтому ключ не отправляется никуда больше. Ключи хранятся только в изолированной конфигурации шлюза (права 600), не попадают в журналы и аргументы командной строки, а в интерфейсе видны только последние 4 символа.
- Если используются только официальные ключи и вход не выполнен, приложение не читает данные аккаунта и каталог цен Modelflare. При вводе ключа приложение один раз запрашивает с его помощью список моделей для проверки, а затем обновляет список каждый час.
- Встроенный шлюз загружает публичный каталог моделей (размер контекста, ориентировочные цены) с `models.dev`. Этот запрос только скачивает данные и не содержит ключей или содержимого разговоров.
- Генерация изображений и видео доступна только через Modelflare.

## Телеметрия

- Телеметрия встроенного Cua Driver отключена: `CUA_TELEMETRY_ENABLED=0` и `CUA_DRIVER_RS_TELEMETRY_ENABLED=0`.
- Во встроенном magpie отключены автообновление и обнаружение аккаунтов; он не читает учётные данные других ИИ-инструментов на компьютере.
- Собственный код AnyModelBot (`src`, `electron`, `ui`, `scripts`, `dsh-runtime/plugins`) не отправляет аналитику или телеметрию: поиск telemetry, analytics, sentry, posthog и mixpanel находит только две переменные Cua выше.
- Сторонние компоненты ведут себя согласно собственной документации; гарантий за них здесь не даём.

## Другие сетевые запросы

Помимо запросов к моделям приложение обращается в сеть, чтобы:

- Читать каталог моделей Modelflare, баланс, расходы и уведомления — данные вашего аккаунта с modelflare.dev.
- Получать формат запроса модели из docs.modelflare.dev при создании изображений и видео.
- В канале WeChat обращаться к `ilinkai.weixin.qq.com` и скачивать ваши изображения и файлы с CDN WeChat.
- Поддерживать постоянное соединение с открытой платформой Feishu.
- После подключения Telegram, Slack и Discord обращаться к `api.telegram.org`, `slack.com`, `discord.com` и их файловым серверам для обмена сообщениями и файлами.
- В Windows при включённом агенте и отсутствии рабочего PowerShell 7 скачивать его с официального адреса Microsoft. Отключение: `AMB_PWSH_AUTO_INSTALL=0`; см. [руководство разработчика](./development_ru.md).
- Установленное настольное приложение проверяет обновления в GitHub после запуска и раз в 6 часов, по умолчанию скачивая файлы обновления в фоне. Автоматическое скачивание можно отключить в «Настройки → Общие». Запросы не содержат учётных данных аккаунта или переписки. Установка требует нажатия «Перезапустить и обновить» и отсутствия выполняющихся задач.
- Когда вы открываете «Что нового» для ещё не установленной версии, приложение загружает её историю изменений с GitHub (`raw.githubusercontent.com`). Запрос отправляется только при открытии и не содержит учётных данных аккаунта или переписки. История изменений установленных версий входит в приложение и не требует сети.
- Приложение получает удалённый каталог ботов и скачивает пакеты по мере необходимости только при явной настройке `AMB_CATALOG_URL`. Подписи и хеши проверяются, ваши данные не отправляются. По умолчанию официальный каталог, интерфейсы, примеры данных и навыки входят в приложение; их открытие и установка не требуют таких сетевых запросов.

## Управление компьютером и снимки экрана

- Чтение экрана создаёт снимки, отправляемые в запросе модели со зрением.
- По умолчанию действия автоматические. В разделе «Настройки бота → Управление компьютером» можно включить подтверждение изменений интерфейса; чтение экрана остаётся автоматическим.
- Ботам с режимом «Только чтение» доступны только инструменты чтения.

## Каналы

- Сообщения с ботами в WeChat, Feishu, Telegram, Slack и Discord проходят через серверы этих платформ и подпадают под их политики приватности.
- По умолчанию общаться могут владелец и разрешённые пользователи. Сообщения остальных не отправляются модели, а записываются как запросы доступа; см. [руководство разработчика](./development_ru.md#кто-может-пользоваться-ботом).

## Удаление данных

1. Выйдите из AnyModelBot через меню трея → «Выйти».
2. Удалите папку данных из таблицы выше. В Docker: `docker rm -f amb && docker volume rm amb-data`.
3. Отзовите AnyModelBot в разделе авторизованных приложений профиля Modelflare.
4. При необходимости отключите созданные приложения Feishu, включая созданные сканированием; отвяжите бота WeChat; удалите созданных ботов Telegram (@BotFather), Slack и Discord; в Notion отключите AnyModelBot и удалите созданные токены.
