## Вопросы и обратная связь

- **Вопросы, идеи, ваши примеры:** [GitHub Discussions](https://github.com/modelflare-ai/AnyModelBot/discussions).
- **Ошибки и пожелания:** [GitHub Issues](https://github.com/modelflare-ai/AnyModelBot/issues), используйте шаблоны.
- **Проблемы безопасности:** не создавайте публичный issue; сообщите приватно по [правилам безопасности](./SECURITY_ru.md).
- **Остальное:** [support@anymodel.bot](mailto:support@anymodel.bot).

В сообщении об ошибке укажите:

- Версию («Настройки → О приложении»), ОС и архитектуру, например Windows 11 x64 или macOS 15 Apple silicon, а также способ запуска: приложение, командная строка или Docker.
- Шаги воспроизведения, ожидаемый и фактический результат.
- Диагностику: «Настройки → Диагностика → Копировать диагностику» — ключи и токены заменяются на `***`. Журналы находятся в `logs/app.log` внутри папки данных; её расположение — в [документе о приватности](./docs/privacy_ru.md#папка-данных).
- ID модели, если ошибка связана с определённой моделью.

## Среда разработки

Требуются Node.js 22.13+ и Go 1.26.8+ для сборки встроенного шлюза magpie.

```bash
git clone https://github.com/modelflare-ai/AnyModelBot.git
cd AnyModelBot
npm install
npm run setup          # получить подмодуль vendor/magpie и собрать его в build/bin/
```

| Команда | Назначение |
| :--- | :--- |
| `npm start` | Запуск из командной строки: шлюз, боты и консоль `http://127.0.0.1:3600/` |
| `npm run dev` | То же с перезапуском при изменении кода |
| `npm run electron:dev` | Настольное приложение в режиме разработки |
| `npm run electron:smoke` | Базовая проверка приложения; без экрана в Linux используется xvfb-run |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm test` | Модульные, автономные сквозные и интеграционные тесты шлюза |
| `npm run test:dsh-bundle` | Интеграционный тест настоящего DSH под Electron; сначала выполнить `prepare:dsh` и `bundle:dsh` |
| `npm run docs:check` | Проверка README |

Структура репозитория, упаковка и настройка каналов описаны в [руководстве разработчика](./docs/development_ru.md).

## Ветки и pull request

1. Сделайте форк и создайте ветку от `master`.
2. Перед отправкой выполните:

   ```bash
   npm run typecheck && npm test
   ```

   Если менялись README или `docs/`, выполните также `npm run docs:check`.
3. Откройте pull request в `master`: что изменилось, зачем и как вы это проверили. Для изменений интерфейса приложите снимки экрана.
4. Для изменений крупнее небольшого исправления — новых функций, архитектуры или зависимостей — сначала создайте issue, чтобы согласовать подход до начала работы.
5. Один PR — одно изменение. Следуйте существующему стилю коммитов: `feat(scope): …`, `fix(scope): …`.

## Изменения интерфейса

- Используйте токены и компоненты `ui/design`; см. `ui/design/README.md`. Не задавайте разовые цвета и размеры шрифта.
- Акцент бренда — яркий жёлто-зелёный `#d7ff00`; не добавляйте в интерфейс синий цвет.
- Консоль использует Preact + htm без сборки. Не добавляйте сборщик или зависимости интерфейса, требующие компиляции.
- Проверяйте светлую и тёмную темы.
- Не вписывайте текст прямо в код интерфейса: добавляйте строки в `ui/locales/zh-CN/` и `ui/locales/en/` на обоих языках и используйте `t()`. Перед отправкой выполните `node scripts/i18n-check.mjs`. Проверяйте оба языка: английский обычно длиннее.

## Сторонний код и зависимости

- Добавляя зависимость или перенося либо адаптируя сторонний код, укажите источник, версию и лицензию в `THIRD_PARTY_NOTICES.md`.
- Не добавляйте компоненты с лицензиями, несовместимыми с распространением под MIT, например AGPL, SSPL или FSL.

## Правила общения

Будьте доброжелательны и опирайтесь на факты. Уважайте каждого участника, обсуждайте идеи, а не людей. Травля, личные нападки и дискриминационные высказывания недопустимы. Сопровождающие могут удалять неподходящий контент. О проблеме можно написать на [support@anymodel.bot](mailto:support@anymodel.bot).
