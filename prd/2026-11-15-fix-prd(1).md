## 二、产品逻辑

- **整行选择框**：占满一整行的菜单按钮。整行可点，文字靠左，下拉三角固定在框内最右侧，展开的列表与框同宽。应用里所有占满一行的菜单按钮都按这个样子显示。
- **生效状态**：装好技能或分配好应用后只有三种说法。

  | 机器人状态 | 成功提示 | 设置列表 |
  | :--- | :--- | :--- |
  | 空闲 | 下一条消息起可用 | 已生效 |
  | 正在跑任务 | 当前任务结束后，下一条消息起可用 | 下一条消息起生效 |
  | 还在加载 | 加载中，下一条消息起可用 | 加载中 |

  加载完成前不能写成已可用。
- **成功提示的结构**：一句结果 + 生效说法；下一行「试试这样说：{示例}」；按钮「填入输入框」（写进当前机器人的输入框并聚焦）和「复制」。
- **工具名**：应用里的某一个能力，如 Notion 的「搜索页面」。
- **小胶囊**：应用现有的小号按钮，浅灰底、正文色、中粗字，圆角胶囊形，宽度随文字。悬停底色加深一档，按下再深一档，指针为手形；键盘聚焦时外侧显示应用统一的焦点描边；深色模式换成对应深色，形状尺寸不变。

**本期不做**：渠道里的过程提示；机器人选用技能和应用的方式；技能详情和作者浮层的内容；设置页行右侧的小下拉；技能列表以外的「应用与技能」按钮；设置里弹窗和侧拉面板内的按钮。

## 三、需求详情

### R1 已登录 Modelflare，左下角账户区显示真实名称和头像（P2）

**现状**：已登录、余额正常，左下角账户行和账户菜单顶部仍是 Modelflare 标志和「Modelflare 账号」，菜单副标题固定写「Modelflare」。目前名称按「昵称 → 自设用户名 → 邮箱 @ 前面的部分」取，都没有才显示「Modelflare 账号」；登录申请的授权范围和 Modelflare 公开的授权范围里都没有邮箱，所以拿不到邮箱。这一条是读代码和 Modelflare 公开配置得出的，没有用真实账号运行核实。

**应有**（左下角账户行和菜单顶部用同一份名称和头像）：

- **名称**，取第一个有值的：① Modelflare 昵称；② 用户自设的用户名（`mf_` 开头的系统生成用户名不算）；③ 完整邮箱；④「Modelflare 账号」。
- **头像**：有 Modelflare 头像就显示（圆形裁切），打不开时按下一条。否则用名称第一个字放在纯色圆底上：中文取第一个字，英文大写，邮箱取第一个字符（数字原样）；同一账号底色固定。名称是「Modelflare 账号」时用 Modelflare 标志。
- **副标题**（只在菜单顶部）：名称是昵称或用户名且有邮箱时显示完整邮箱，否则显示「Modelflare 账号」。
- **过长**：名称和副标题单行显示，末尾省略，悬停显示全称。
- **刷新**：与余额一起刷新（启动、登录成功、切回窗口、每处理完一件事、点「重新读取账号信息」），网页改了昵称或头像切回即更新。本机记住上次的名称和头像，启动时先显示；退出登录时清除。
- **设置 › 模型「Modelflare 账户」**：名称与左下角相同；名称是昵称或用户名且有邮箱时写「{名称} · {邮箱}」，名称本身是邮箱时只写一次。没有昵称时右侧保留「设置昵称 ↗」。
- **不变**：读取中和读取失败的占位、重试入口、「正在连接…」；未登录或用自己的 API Key 时仍是「我的账号」和「本机用户」。

### R3 新建会话直接切到新对话，不发「/new」、不卡在「思考中」（P2）

**现状**：点新建按钮或「+」菜单「开始新的一段对话」，实际是替用户发「/new」：出现「/new」气泡和「思考中」，等模型把旧对话最近 40 条写成交接便条（几秒到十几秒）才回复；这两条不保存，刷新后消失。已是新对话、代理没启用、出错时也先出气泡再回一句。生成中右上角按钮置灰不说原因，「+」菜单这一项点了没反应。渠道里发「/new」要排队并等便条写完，期间没有「正在输入」。气泡和「思考中」来自实际截图，其余是读代码得出的，没有逐一运行核对。

![新建会话现状截图](https://amb-product-docs-1471661522.cos.ap-shanghai.myqcloud.com/anymodelbot/76e607fb8d2e9a7c/images/2026-11-15-fix-3/fix3-new-session-before.png?v=20261115-1)

*截图：当前点新建后，对话末尾出现「/new」气泡和「思考中」。*

**应有**：点新建 = 立即开始新对话，交接便条在后台写。

- **入口**：新建按钮、「+」菜单项、手动输入「/new」行为相同，「/new」后的文字忽略。
- **点下去**：按钮显示按下状态，对话末尾立刻出现灰色分隔线「已开始新对话」，滚到底部，输入框获得焦点，欢迎示例收起；不出现「/new」气泡、「思考中」和回复；手动输入时输入框清空。
- **分隔线**：只画在用户主动开新对话的位置，机器人自动换段不画；保存下来，刷新或重开后仍在原位置。
- **交接便条**：先存旧对话最后 6 条原文（最多 4000 字）作兜底，同时后台把最近 40 条写成便条，写好后替换兜底；写失败（模型不可用、额度不足、网络错误）不提示，继续用兜底。
- **新对话第一句**：便条写好就照常回答；还在写最多等 8 秒，期间照常「思考中」和计时；超时用兜底原文回答，之后写好的便条不再补进。第一句之后不再等。
- **其他情况**：

| 情况 | 应用内 | 渠道（微信、飞书、Telegram、Slack、Discord） |
| :--- | :--- | :--- |
| 正常开始 | 只出现分隔线 | 立即回复，不等便条；前面有未处理的消息时排在后面，轮到即回；第一句等便条规则同应用内，期间显示「正在输入」 |
| 已经是新对话（分隔线后没发过消息，或从没聊过） | 不加第二条分隔线，轻提示约 2 秒，输入框获得焦点 | 回复对应文案 |
| 正在生成回复 | 按钮和菜单项置灰，悬停提示，结束或停止后恢复；手动输入「/new」排在回复后面，结束后立即开始 | 排在当前消息后面 |
| 代理没有启用 | 按钮照常可点，不出现分隔线，底部提示 | 回复对应文案 |
| 开新对话本身出错（不是便条出错） | 去掉分隔线，停留在原对话，底部提示 | 回复对应文案 |

- 各提示和回复的文字见下表；「/help」里 /new 的说明同步改。

| 分隔线 | 已开始新对话 | New conversation started |
| 已是新对话轻提示 | 已经是新对话了 | You're already in a new conversation |

**验收**：

- 聊过几轮后点新建：立刻出现分隔线，输入框获得焦点，没有「/new」气泡、「思考中」和回复；「+」菜单和手动「/new」结果相同。
- 刷新、重启后分隔线仍在原位置。
- 新建后马上发第一句：8 秒内开始回答，期间是正常「思考中」；问「我们刚才在聊什么」能接上。
- 把整理便条的模型设成不可用：仍立即出现分隔线，约 8 秒内用最后几条原文接上，无出错提示。
- 新建后不发消息再点：不出现第二条分隔线，提示「已经是新对话了」。
- 回复过程中：新建按钮和「+」菜单项是灰的，悬停有提示；停止后恢复。
- 微信里发「/new」：几秒内收到「已开始新对话。……」；再发一句能接上旧对话。
- 英文界面和英文渠道按上表显示。

### R4 过程区的应用行带上工具名（P2）

**现状**：过程区只写「正在使用 Notion」，连调几个工具也只一行，结束后折成「已使用：Notion」，失败写「没能使用 Notion。{原因}」，看不出在做什么。以上是读代码得出的，没有实际运行核对。

**应有**：

- 调用中每个工具一行「正在使用 {应用} · {工具}」；同一应用的不同工具各占一行，同一工具多次调用只算一行。
- 失败行「没能使用 {应用} · {工具}。{原因}」，原因用现有短话，不露内部报错。
- 折叠行「已使用：{名称1}、{名称2}」，应用项写成「{应用} · {工具}」；全部失败时「没能使用：…」。展开后的细节、「用时 {n} 秒」、技能行及其可点开详情不变。
- 工具名优先用应用提供的显示名称，没有时用工具名原文。应用行仍不能点。只在电脑端对话里显示。

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 调用中 · 应用 | 正在使用 {app} · {tool} | Using {app} · {tool} |
| 失败 · 应用 | 没能使用 {app} · {tool}。{reason} | Couldn't use {app} · {tool}. {reason} |
| 折叠后 · 应用项 | {app} · {tool} | {app} · {tool} |
| 折叠后 · 多项 | 已使用：{name1}、{name2} | Used: {name1}, {name2} |

**验收**：

- 让机器人用 Notion 先搜再读：先后出现「正在使用 Notion · {搜索工具}」「正在使用 Notion · {读取工具}」，结束后折成「已使用：Notion · {搜索工具}、Notion · {读取工具}」。
- 同一工具连续调用 3 次只有一行。
- 断开 Notion 后让它搜索：显示「没能使用 Notion · {搜索工具}。请检查「Notion」的连接。」，无原始报错。
- 英文界面为「Using Notion · {tool}」「Used: …」；技能行显示和点击不变。

### R5 导入 ZIP、分配应用后的成功提示带示例和按钮（P2）

**现状**：机器人设置里导入技能 ZIP 成功只弹「已导入「{name}」，下一条消息起可用。」；输入框「+」›「技能与应用」里点「分配给这个机器人」只弹「已把「{app}」分配给「{bot}」，现在就能用。」。两处都没有示例句和按钮。以上是读代码得出的，没有实际运行核对。

**应有**：

- 两处都按「成功提示的结构」显示；结果句和生效说法保持现有文字，只在下面补示例行和按钮。
- 示例来源：技能库里有触发方式的用那一句；库外或 ZIP 导入的技能用描述第一句，没有则「用{名称}帮我……」；应用用应用页同一句示例，没有则「用{应用}帮我……」。
- 「填入输入框」写进这个机器人的输入框并聚焦；导入 ZIP 时先切到这个机器人最近一条对话再填入。应用内群聊里只显示「复制」。
- 带按钮的提示不自动淡出，右侧有关闭按钮，点任一按钮或关闭后收起。

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 示例行 | 试试这样说：{example} | Try saying: {example} |

## 四、技术前提

1. 应用要能从 Modelflare 读到邮箱和头像地址（账户资料接口直接返回，或在应用申请的授权范围内由用户信息接口返回）；Modelflare 不提供的字段按「有就用，没有就跳过」处理。
