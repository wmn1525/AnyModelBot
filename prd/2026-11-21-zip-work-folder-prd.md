## 一、业务背景与要解决的问题

用户已有一份其他工具产生的工作产物，需要让机器人继续读取、修改和完善。产物可能已经在电脑的一个文件夹里，也可能以 ZIP 形式交接。

**现状（v0.1.44）**：对话只能接收图片和文本文件（每件 10MiB），文件的完整文字直接交给模型；压缩包、文件夹都加不进来。机器人的文件操作默认只在它自己的工作区（应用数据目录下 `workspaces/<机器人>`）里可写，用户要处理桌面上的项目，只能在指令里手写路径，越界写入每次都要批准。

**典型场景**：

1. 用户在桌面版选中 `~/Projects/landing-page`，说「把首页标题改成英文，再检查一下有没有失效链接」，机器人直接在原文件夹里改。
2. 同事发来 `报价单资料.zip`，用户拖进对话说「解压后把里面的表格汇总成一份 Markdown」，机器人在受管空间解压并给出汇总。
3. 用户选了目录 A 并发出一个耗时任务，等待期间切到目录 B 发新指令；两件事各自只动自己的目录。

**目标**：文件夹选好位置即可发指令；ZIP 直接拖入即可交给机器人按指令处理，不要求用户重新逐个添加文件。

### 术语（r2）

| 术语 | 含义 |
| --- | --- |
| 目录引用 | 用户在系统选择器里确认的那个文件夹的定位信息（真实路径＋宿主标识＋校验所需的元信息），不含任何文件内容 |
| 宿主 | 运行这个机器人的那台机器（桌面版即本机；Docker／命令行部署即服务器） |
| 会话分段 | 同一对话里用户每「开始新的一段对话」（`/new`）一次就进入新分段；「清空上下文」不产生新分段。与 v0.1.43 起待发附件使用的分段一致 |
| 绑定 | 点击发送那一刻把目录引用（或「无目录」）固定到这条消息上，此后的排队、审批、重试都只认它 |
| 默认工作区 | 机器人原有的工作区 `<数据目录>/workspaces/<机器人>`，未选择目录时的读写目标 |
| 受管附件处理空间 | 应用为每个对话分段管理的附件解压位置，随附件到期清理；不属于用户目录 |

## 二、产品逻辑与范围

- **工作文件夹**：输入框上方选择目录，只保存位置引用。用户发指令后才按需调用文件能力，在原位置读写；选择本身不读取、上传或复制目录内容，不发送消息、不启动任务。
- **ZIP 附件**：拖入输入区，以普通文件附件接收。上传仅保存文件；用户发出处理指令后才读取或安全解压，不自动运行项目。
- 两个入口独立，加号不改；目录不占附件数量或容量，也不因目录大、文件多或为空而不能选择。
- 目录在当前机器人、当前对话的当前分段持续保留；新对话初始未选择。每条消息绑定发送时的目录引用，后续更换不重定向已提交任务。
- 首版目录选择限运行机器人所在机器的桌面端；ZIP 在支持标准文件拖放的桌面／网页端接收，不另加文件选择按钮。所有界面复用当前灰色组件，不增加项目管理页面。
- 中英文文案如下，各已支持语言在同一版本按中文语义同步，不保留旧入口或旧限额文案。
- （r2）**适用对象**：

| 场景 | 目录选择 | ZIP 拖入 |
| --- | --- | --- |
| 桌面版应用内的普通对话（自建机器人） | 提供 | 提供 |
| 网页端（命令行 `npm start`、Docker 或远程浏览器打开的管理界面） | 不提供，选择器禁用并提示（R3） | 提供 |
| 目录 Bot（含其专属界面里的输入框） | 不提供；文件范围仍由 Bot 声明的权限决定 | 按普通附件接收；解压与读写受 Bot 声明的权限约束，未声明 `workspace-write` 时按「只读」档处理（R7） |
| 代理模式关闭或找不到代理运行时（只能纯对话） | 不提供，提示开启代理模式 | 不接收，提示原因；图片／文本附件照旧 |
| 微信、飞书、Telegram、Slack、Discord 等聊天渠道发来的消息 | 不适用：始终使用默认工作区，不受界面里任何目录选择影响 | 不在本期范围，渠道文件处理保持现状 |

**本期不做**：文件夹上传、选择时的内容扫描、目录树／统计／已读状态面板、上传目录的进度、目录副本管理、自动成果打包、项目创建、仓库克隆、远程目录浏览、云同步、技能安装或记忆迁移；（r2）同一条消息绑定多个目录、按目录设置不同权限档位、`.docx`／`.xlsx`／`.jar`／`.apk`／`.epub` 等以 ZIP 为容器的格式按 ZIP 处理、tar.gz 等其他压缩格式、聊天渠道里的目录或 ZIP 处理。

## 三、需求详情

### R1 输入框上方选择工作文件夹

- **入口与显示**：上方左侧仅一个「文件夹图标＋选择文件夹＋下拉箭头」。下拉仅含最近文件夹（有记录才显示）、「选择文件夹…」、「不使用文件夹」；不加搜索、项目创建或多层菜单。当前项打勾。
- **选择成功**：点「选择文件夹…」打开系统原生目录选择器；确认后立即显示根目录名并收起菜单，不二次确认，不等待扫描或准备。空目录合法；支持系统允许的中文和 Unicode 名称。
- **更换与取消**：点已选目录名可选最近项或重新选择；取消系统选择保留原值；「不使用文件夹」清除当前选择，后续消息回到机器人原默认工作区。不删除文件，不停止已提交任务。
- **名称与路径**：长名截断，悬停显示完整本地路径；最近项同名时附父路径区分。不将这些显示路径自动拼入模型消息；运行层根据目录引用定位实际文件。
- **最近目录**：当前本地用户身份、当前运行实例最多保存最近 10 项；按系统识别的同一真实目录去重（设备号、inode 和创建时间；删掉再建的同名目录不算同一个），不按显示名去重。重新选择移至首位，超出移除最早记录，不删除真实目录；不同机器同名路径不合并。
- **历史失效**：显示最近列表不读取文件、不后台检查内容。用户点选时只核验目录本身的位置与必要访问条件；失效项短提示重选，保留原活动选择，不自动寻找同名目录或换根。
- **状态**：未选择 → 系统选择 → 已选名称；系统取消回原状态。下拉说明只描述选择动作（选择时不读取），并如实告知之后会按指令在这里读写（见 R7 权限矩阵），不限制之后按指令读取。
- （r2）**不可选位置**：系统选择器返回以下位置时不生效，短提示并保留原选择：① 应用数据目录及其任何子目录（含默认工作区、附件存储、受管附件处理空间——机器人对数据目录本就无权读取），以及数据目录的任何上层目录（r3：选了上层，数据目录就落进可写范围）；② 磁盘／卷的根（如 `/`、`C:\`）；③ 当前系统用户的主目录本身（其下的子文件夹可以选）。判断按真实路径，符号链接、快捷方式指过去的同样不可选。这条不受「目录大、文件多不影响选择」约束：拒绝原因是范围，不是体积。
- （r2）**与现有控件共存**：输入框左下角的「文件权限」胶囊、加号、模型选择保持原位与原行为；目录选择位在输入框外侧上方，不放进附件托盘，不计入「n/8 个附件」。窄窗口下目录名先截断，选择位不换行、不挤掉权限胶囊。

### R2 会话保持与每条指令绑定

- **保持范围**：同一对话当前分段发完消息不清空目录；离开再返回恢复其引用。新建或开始新对话均不带入旧选择，即使底层对话标识复用也需按新分段隔离；不同机器人、对话和实例不串目录。
- **重启恢复**：恢复目录引用和显示名，不恢复文件内容、不自动续跑任务。实际访问再核验原位置与权限；无法确认仍指原选目录时提示重选，不操作新出现的同名替代目录。没有选择时只回机器人原默认工作区，不扩大到主目录或整盘。
- **发送绑定**：点击发送捕获当时目录引用、运行宿主标识及对话分段；无选择时也固定本条消息的默认工作区目标。只记录定位元信息，不携带整目录内容。服务端验证身份、宿主与引用归属后受理，不以后台后来变更的活动目录替换请求目标。目录是否仍可访问在实际文件操作前校验，纯聊天不因所选目录暂不可用而被阻止。
- **排队／审批／重试**：使用同一条消息已经绑定的位置；更换或取消目录只影响之后新发送的指令。进行中的任务和已等待批准的操作仍指原目标；拒绝批准不改到其他位置执行。不强制每条指令重新选择目录。
- **受理不明**：只查询原请求回执，保留原绑定，不允许重复提交新任务；若明确未受理，文字与附件保留，用户下一次主动点击发送才捕获当时的新选择。已提交请求的重试不得读取选择器的新值。
- **指令解析**：「这个文件夹」、相对文件名及该目录任务的新文件默认以本条绑定目录为目标。用户明确给出其他绝对路径时，先核验其在机器人宿主可访问并按权限处理，不默默更改选择器。无法访问时说明原因，不退回默认工作区或全盘搜索。
- **不是内容快照**：读取的是工具执行时的真实内容；外部修改、删除、改名或权限变化可能影响任务。查看同一会话的旧消息，不以旧消息绑定的目录替换当前选择，也不自动重跑旧文件操作。机器人全局默认工作区设置和共享进程的默认工作目录不因选择器改变。
- （r2）**清空上下文**：「清空上下文」不进入新分段，所选目录保留；只有「开始新的一段对话」（`/new`）清除。两者对待发 ZIP 的处理与 v0.1.43 待发附件一致。
- （r2）**补充给进行中的回复**：补充并入正在进行的那一轮，沿用该轮绑定的目录。若发出该轮之后选择器已改为别的目录（或取消），本轮结束前不显示「补充」按钮，输入只能作为新消息在本轮结束后发送并绑定新选择，避免用户以为补充会改用新目录。
- （r2）**派生工作**：本条消息里机器人启动的子代理、后台任务继承本条绑定（任务的工作目录就是绑定目录，新文件写在那里；任务的会话记录仍由应用照旧管理）；任务在之后的轮次也不读取选择器的新值。定时规则、其他机器人交来的事、聊天渠道的消息与选择器无关，一律用默认工作区。
- （r2）**命令消息**：`/status`、`/model`、`/new` 等斜杠命令不绑定目录、不触发文件操作，也不改变当前选择。

**验收**：A 目录消息排队、等待批准或网络重试时切为 B，原消息仍指 A，新消息才指 B；取消选择也不重定向旧任务。新分段、切机器人不带入旧值；重启仅恢复引用。替换同名目录、丢失权限或更换宿主后不误操作其他位置；返回旧消息不切目录。（r2）「清空上下文」后目录仍在，`/new` 后为空；A 目录回复进行中切到 B 时不出现「补充」；A 目录消息启动的后台任务在切到 B 后的轮次里仍只写 A；从微信等渠道给同一机器人发「整理这个文件夹」，操作的是默认工作区而不是界面里选的目录。

### R3 同机选择与多端边界

- **支持范围**：macOS、Windows、Linux 桌面应用中，能验证客户端与机器人同机的连接启用原生目录选择；桌面能力与宿主身份由应用协商并由服务端验证，不凭浏览器标识、同名路径或伪造字符串认定同机。
- **不支持选择的端**：网页及连接其他宿主的客户端不提供本机目录选择／更换，选择器禁用并短提示；不调用远端机器上的系统选择框，不用上传文件夹替代。普通聊天及客户端支持的 ZIP 拖入不受此限制。
- **已存在的会话选择**：从其他端进入同一会话时，只显示其已绑定的宿主目录名，不能改成本端同名目录；新指令仍使用该会话合法的宿主目录引用并接受同样的权限校验。未绑定时使用机器人默认工作区。
- （r2）**现状对照**：v0.1.44 的桌面版总是在应用进程内运行机器人，窗口经每次启动生成的随机令牌访问本机界面，因此「桌面版窗口」即同机；目前没有连接其他宿主的桌面客户端。上面的宿主校验规则是为了在以后加入远程连接时仍然成立，本期不需要为它做远程连接功能。命令行 `npm start` 即使在同一台机器上用浏览器打开，也按网页端处理（没有可用的原生选择器）。
- **文字路径**：用户在指令里写路径，只可能定位机器人宿主上的文件，不代表授权读取浏览器所在电脑；仍受文件工具权限、系统访问限制及实际可达性约束。不能用文字路径绕过上述限制。

| 位置 | 中文 | English |
| --- | --- | --- |
| 目录选择不可用 | 请在运行机器人的桌面端选择文件夹 | Choose a folder in the desktop app on the bot's machine. |
| 宿主不可达 | 当前无法连接运行机器人的设备，请连接后再试 | Can't reach the bot's machine. Reconnect and try again. |

**验收**：三种桌面系统分别能调用本机原生选择器；网页及远端目录入口禁用，支持文件拖放时 ZIP 可用。两台机器相同路径不认作同一目录，伪造宿主／目录引用被拒；已有会话的宿主目录不会被客户端路径替代。

### R4 ZIP 拖入、附件数量与容量

- ZIP 直接拖入输入区，不增加 ZIP 选择按钮，不改加号。文件夹拖入不加入附件、不展开扫描，只提示使用上方选择器。
- 待发 ZIP 仅普通文件图标、文件名、大小和独立「×」；移除立即消失并释放配额，无撤销／恢复提示。已发附件位于正文上方、同组右对齐，只显示图标、名称与大小，无待发「×」；没有文字也能单独发送 ZIP。待发卡点击只聚焦；已发卡点击保存原 ZIP（桌面打开系统另存为，网页下载，均保存到当前操作端，不在另一台机器弹框），不解压、不执行、不打开资料面板；到期或无权短提示。
- 支持 `.zip` 及大小写变体；按真实签名与结构校验，不信任后缀或 MIME。零字节文件拒绝；合法的空 ZIP 可以接收。RAR／7z／tar 等不作为 ZIP 接收。
- （r2）只有扩展名为 `.zip` 的文件走 ZIP 规则：`.docx`、`.xlsx`、`.pptx`、`.jar`、`.apk`、`.epub` 等内部同为 ZIP 结构的文件仍按原规则提示格式不支持，不因签名相同而被当成 ZIP 接收；反过来，扩展名是 `.zip` 而内容不是合法 ZIP 的文件按「格式」拒绝。
- 每个 ZIP 占 1 个附件，不算图片；不同 ZIP 和图片／文本共用本条消息的数量、总量配额，不把包内文件数计入附件数。工作目录不计入这些限制。
- （r2）ZIP 不计入文本附件的字数限额（单份 10 万、单条 20 万字符）和「附件内容超出当前模型上下文」的预估，也不要求当前模型支持图片；这些检查只针对随消息直接交给模型的图片和文本。

### R5 ZIP 接收、发送、取消与保留

- **待发状态**：添加 → 接收中 → 普通文件卡；接收中不可发送本条消息，不自动发出。失败／过期仅短原因，用户用「×」移除后重新拖入；原文字和其他合法附件保留。无资料详情页、目录树、解析进度或已读状态。
- **真实接收**：完整接收并验证字节后才可发送，ZIP 不按文本解码或全量塞进模型。源 ZIP 读取失败或检测到源文件大小／版本变化，本项失败，不提交半份；接收成功以这次实际字节为准，之后不跟踪源文件变化。接收中断不做断点续传，重新拖入从头接收。
- **发送受理**：受理前再次核验身份、机器人／会话分段、附件版本、状态、配额和目录绑定；条件变化拒绝本次，保留原输入。受理后附件只绑定一条消息，清空已发待发项但不清空工作目录。
- （r2）**模型收到什么**：每个 ZIP 只以一行附件说明随消息交给模型——文件名、字节数，以及本会话文件工具可以取用它的位置；不附包内文件列表、不附任何包内内容。图片、文本附件仍按 v0.1.43 的方式直接交给模型。历史消息里的 ZIP 在到期前同样可按这一位置取用，到期后说明里标明已过期。
- **防重**：同一请求标识固定文字、附件版本和目录／宿主引用；发送状态未知时查询原回执，暂禁再次提交。已受理返回同一消息及任务，不重复启动处理；明确失败后用户可重新点击发送。用户主动另发同样内容属于新指令，不与网络重试混为一谈。
- **隔离**：ZIP 及工具取用引用按本地用户身份、机器人、会话和消息校验，不因知道文件名或附件标识就可跨范围读取。切机器人／新对话不带走旧待发 ZIP；已发送的合法引用不因界面切换而改属。
- **取消边界**：选择文件后取消读取／上传或移除待发项，只停止尚未受理内容的后续提交并回收其暂存，不等于撤回已经受理的消息或停止已有任务。任务另由当前任务停止操作处理，不新增撤回入口。
- **保留规则**：未发送 ZIP 自创建暂存记录起最多 24 小时；已发送 ZIP 自消息受理起保存 30 天。到期清理受管附件字节，历史消息保留名称并短提示重新拖入，不能假装仍能重新读取。默认受管解压目录随所归属附件到期或删除清理；到期先拒绝新取用，正在进行的合法原子文件操作结束或停止后释放占用再回收，不在操作半途删除临时文件，也不因此重置到期时间；已按指令写到用户工作目录的文件和用户下载文件不参与此清理。
- **目录独立**：目录引用不受附件到期时限影响；删除对话只清理该对话的引用及受管附件，不删除所选原目录或其中的用户文件。未发附件不承诺跨浏览器重启恢复；失去暂存引用时提示重新拖入。

### R6 按指令安全解压

- **触发与位置**：拖入或发出 ZIP 都不自动解压、执行或安装依赖。用户要求查看、解压或继续处理时才调用相应文件工具；只发附件未说明任务时，在对话里询问要怎么处理，不自动解包或推定允许执行脚本。默认在受管附件处理空间中新建不重名目录解压，选择工作目录不会自动把 ZIP 放进去。解压完整成功后才提供可用位置，不让机器人基于失败留下的半份内容继续任务。
- **指定目标与冲突**：用户明确要求解到工作目录或其他目标时，核验目标并取得需要的批准。仍先新建不重名解压目录，已有同名目录则创建另一个名称；不直接覆盖或合并已有文件。用户要求合并／替换时作为后续文件操作按明确指令及批准执行。
- （r3 改）**受管解压目录的归属**：解压目录在机器人默认工作区的 `extracted/` 下（每次新建不重名的子目录），登记在所属附件名下，随附件到期或删除回收。和工作区里的其他文件一样，同一机器人的其他对话也看得到，其他机器人不可取用；原始 ZIP 只能由它随消息发出的那个对话取用。它在权限矩阵中单列（R7）。回复里告诉用户解压位置时用「已解压（共 N 个文件）」之类的说明，不展示数据目录里的真实路径；用户需要拿到文件时按 R7「交付」处理。
- **接收与解读分开**：接收只做可验证的格式及存储检查，不声称已读懂内容；完整校验在按指令处理时完成。可安全保存／解压的 PDF、Office、图片或其他二进制文件，不代表机器人新增了预览、解析、编辑能力；不能理解的内容保留原文件并在对话中说明，不因这个原因整包拒绝。

### R7 按指令读写原位置与处理结果

- 收到任务后才按任务需要读取相关文件；选择本身不预读说明或遍历目录。用户要求整理／遍历目录时，可在任务范围内调用文件工具，不产生独立扫描或读取状态界面。相关内容可能交给当前所选模型处理；（r2）本条绑定目录的真实路径会作为运行环境的一部分交给模型（与现在默认工作区路径的处理一致），用户消息正文里不自动拼入路径；长文件按需读取，不把全目录一次性塞入上下文，也不能伪称所有资料均已理解。
- 文件夹任务处理原件，修改／新增位置遵循用户指令及本条目录绑定，不能保证原件不改；目录自身变化、权限失效或宿主不可达时简短失败，不后台巡检、重找或全盘搜索。

| 本条所选目录（含子目录） | 只读；命令在只读沙箱运行 | 读写；命令可写这里，无需逐次批准 | 读写，与现有完全权限一致 |
| 受管解压目录（`extracted/`） | 可由解压工具写入；其余只读 | （r3 改）未选目录时读写；选了目录的那条消息里只读（解压工具照常能写；要改解出来的文件，请解到工作文件夹） | 读写 |
| 机器人默认工作区 | 只读 | （r3 改）未选目录时读写（保持现状）；选了目录的那条消息里只读 | 读写 |
| 其他位置 | 只读（应用数据目录除外，始终不可读） | 可读（数据目录除外）；写入、移动、删除需批准 | 与现有完全权限一致；递归删除仍需批准 |

- （r3）**为什么选了目录时默认工作区只读**：DSH 的沙箱（文件工具，以及 Linux bubblewrap、macOS Seatbelt、Windows ACL 的命令沙箱）每次调用只有一个可写根。所以「工作区可写」下，所选目录在这条消息里取代默认工作区，而不是两处都可写。写到可写根之外时，沙箱先拒绝；模型申请提权时才出批准卡，用户允许后只放行这一次。
- （r2）「工作区可写」的胶囊说明「只能改这个机器人的工作区，越界操作先问你」在选了目录后仍然准确：所选目录就是这条消息的工作区。不为此改动权限胶囊文案或增加新的权限开关。
- 系统文件夹访问限制和工作区批准分别生效；系统拒绝时仅说明实际文件访问缺项；该系统有可用访问设置入口时才提供引导，不承诺一定弹框，不循环发起请求。仅处理文件不以屏幕录制／辅助功能为前提，不新增危险权限开关或每条消息的额外确认。
- 选中的根及子路径仍接受真实路径校验；符号链接指向其他位置时不自动扩大授权，需按真实目标及权限处理。选上层目录不等于允许读取账号、凭据或无关文件。
- 目录或 ZIP 内的说明、脚本、HTML 都是任务资料，不自动当成系统指令、安装技能、联网或运行。任务实际需要执行命令时按真实操作与批准链执行，选择／拖入本身不授予执行权限。
- 结果按指令正常回复、保存文件或提供可下载文件；不要求成果页、强制修改清单或最终 ZIP。用户要求下载／打包时才生成相应文件并走有权文件交付；无权、失效或生成失败时短提示，不展示假下载成功，也不自动覆盖用户原位置。

**验收**：选目录或拖 ZIP 不触发执行；按指令处理指定文件可在原位置修改，需批准时出卡且允许／拒绝有效；目录外链接不扩大授权。包内格式不能解析时如实说明，不虚称已理解；没有打包指令不强制生成 ZIP，下载失败不报成功。（r2）「工作区可写」下选目录 A 后让机器人改 A 里的文件、在 A 里运行会写文件的命令，均不出批准卡；同时要求写目录 A 之外的文件时出卡。同一机器人另一个对话绑定目录 B 时，本对话写 B 需批准。「只读」下选目录后要求修改，按现有只读提示说明不能写入；ZIP 仍可解压到受管空间并读取。Linux 上 bubblewrap 不可用（命令被拒）时，文件读写工具仍能处理所选目录，命令失败按现有提示说明。

## 四、技术前提

1. 桌面原生目录选择、目录引用的本机保存与真实位置校验、宿主身份及能力协商接通；网页不能冒用桌面选择能力或将路径字符串当文件访问授权。
2. 会话分段与每条消息的目录／宿主绑定贯穿受理、排队、工具读取／写入／命令、批准、重试和恢复；不通过修改机器人共享进程的全局工作目录实现，不跨任务改变目标。
3. ZIP 二进制附件、统一前后端限额、部分接收、实际字节校验及幂等回执接通；当前会话的文件工具能真实取得合法 ZIP 引用，不能只生成卡片／文件名，也不能开放整个附件存储目录。
4. 受限解压具备真实路径校验、资源中止及仅清理本次文件的能力；受限解压失败不能改用不受限命令绕过；受管附件／解压文件与用户原位置文件归属分离，回收不能删除用户原目录或明确交付到其中的文件。
5. （r2）**按消息切换可写范围**：v0.1.44 每个机器人一个代理子进程，沙箱可写根固定为默认工作区（Linux 的 bubblewrap 包装脚本只绑定这一处），会话工作目录可以单独设置但不改变沙箱根。本需求要求文件工具与命令沙箱的可写根随每条消息的绑定切换，并且只对该会话的该轮生效；不能用重启共享子进程、修改全局工作目录或把所有会话用过的目录并入同一可写范围来实现。macOS（Seatbelt）和 Windows 上的命令沙箱同样要满足。（r3）实现方式：代理进程里的 `amb-workfolder` 插件改写沙箱策略，让这个会话（及其子代理）的工作区根解析为绑定的目录；宿主在每一轮开始前经指令通道告知，并把会话工作目录换过去。告知失败这一轮就不跑（fail closed）。
6. （r2）**数据目录隔离不变**：代理对应用数据目录的读取禁止（当前只对默认工作区和代理主目录放行）继续有效；受管附件处理空间如放在数据目录内，只能按 R5、R6 的归属为对应分段单独放行，不能放行整个附件存储目录。
7. （r2）**同机判定**：目录选择接口只接受来自桌面版窗口（带启动令牌、同进程外壳）的请求，并由外壳调用系统原生选择器、把结果直接交给运行层；网页请求即使带上路径字符串也不能生成目录引用。

## 八、决策记录（r2，已确认）

以下几项原文没有明说或与现有实现有冲突，r2 已按下列结论写入正文。记录理由，供实现和后续修订时对照：

1. **所选目录免批准可写**：在「工作区可写」下，所选目录在本条消息内取代默认工作区（R7 权限矩阵）。否则用户每改一个文件都要点一次批准，与「继续修改和完善」的目标冲突。
2. **不可选位置**：拒绝数据目录、磁盘根和主目录本身（R1）。数据目录必须拒绝（代理本就无权读取）；后两项是因为第 1 项把免批准写入范围交给了所选目录，范围不能大到整盘或整个主目录。
3. **只读档位下的 ZIP 解压**：允许解压到受管空间（不触碰用户文件），否则只读用户无法让机器人看 ZIP 里的内容；不允许解到所选目录或其他位置。
4. **逐项校验的范围**：所有拖入和粘贴都改为逐项校验，不只针对 ZIP，避免同一个拖放区出现两套规则（R4）。
5. **目录 Bot、代理模式关闭、聊天渠道**：本期都不提供目录选择（第二节适用对象表）。
6. **补充按钮**：切换目录后、本轮结束前隐藏「补充」（R2），避免用户误以为补充会改用新目录。
7. **所选目录内删除不另行批准**：与默认工作区的现有规则一致，不为所选目录单独加删除批准；完全权限下的递归删除闸门照旧。若上线后误删反馈集中，再考虑只对所选目录内的删除、移出操作出批准卡。
